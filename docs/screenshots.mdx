These captures show the current ctrl-π interface with `MockYAMDriver`, the
synthetic camera, and Stub compute. The Datasets and Models views use the
server-configured Hugging Face namespace. A screenshot demonstrates the UI
state only; it is not evidence that a physical YAM or a cloud workload was
validated.

## Overview

Overview answers "what is this cell doing right now": connected robots,
captured episodes, training progress, deployment state, recent activity, and
service readiness. Safety warnings such as `NO SASH GUARD` surface here first.

## Robots

Robots lists every configured arm; opening one shows its connection and joint
state first, with pose, gripper, pair alignment, diagnostics, identity, and
manual jog collapsed under Details. Manual jog remains bounded and requires a
connected arm; the supervised all-CAN adapter rejects one-shot jog. See
[Robots](/arms) for the hardware safety boundary.

## Training

Training is a first-class observer for externally reported runs and managed
jobs launched through the SDK/REST API. The run list opens a dedicated detail
page with large metric charts, bounded console output, checkpoints, and
configuration. See [Training](/training), [Managed training]

## Models

Models is a separate read-only catalog backed by Hugging Face. The table lists
repositories and their immutable revisions; opening a row reveals the card,
base models, and checkpoint files. Artifact uploads stay in the user's existing
Hub tooling. See [Models](/models).

## Inference

A deployment is created through a Model → Robot → Compute → Deploy flow, then
gets its own page: live latency, rates, and queue depth, with explicit start
and stop gates. Stop performs provider teardown verification. This capture uses
the deterministic local stub. See [Inference](/inference).

## First-time YAM setup

Settings → Robots guides a cell through passive discovery, bounded
configuration, calibration-artifact preflight, persistence, and an explicit
connection. Hardware connection and automatic restoration require separate
motion-risk acknowledgements. The mock-ready state below does not detect,
calibrate, connect, or validate a physical YAM. See [YAM setup](/yam-setup).
