These captures show the current ctrl-π interface with `MockYAMDriver`, the
synthetic camera, and Stub compute. The Datasets and Models views use the
server-configured Hugging Face namespace. A screenshot demonstrates the UI
state only; it is not evidence that a physical YAM or a cloud workload was
validated.

## Arms

Inspect the selected arm's connection, bus, joint state, end-effector pose,
gripper, and live loop diagnostics. Manual jog commands remain bounded and
require a connected arm. See [Arms](/arms) for the hardware safety boundary.

## Datasets

immutable revision's episodes, synchronized state/action values, and video.

## Training

Training is a first-class observer for externally reported runs and managed
jobs launched through the SDK/REST API. It renders bounded metrics,
checkpoints, sanitized console lines, provider lifecycle, artifact identity,
and teardown truth. See [Training](/training), [Managed training]
(/managed-training), and the [Trainer API](/trainer-api).

## Models

Models is a separate read-only catalog backed by Hugging Face. It shows model
cards, immutable revisions, and checkpoint metadata; artifact uploads stay in
the user's existing Hub tooling. See [Models](/models).

## Inference

Select an immutable policy revision, deploy its endpoint, then explicitly
start robot execution only after endpoint and follower readiness are
authoritative. Stop performs provider teardown verification. This capture uses
the deterministic local stub. See [Inference](/inference).

## First-time YAM setup

Settings guides one leader/follower pair through passive discovery, bounded
configuration, calibration-artifact preflight, persistence, and an explicit
connection. Hardware connection and automatic restoration require separate
motion-risk acknowledgements. The mock-ready state below does not detect,
calibrate, connect, or validate a physical YAM. See [YAM setup](/yam-setup).
