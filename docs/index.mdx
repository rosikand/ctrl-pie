ctrl-π is an engineering console and typed Python API for the YAM
robot-learning loop. It brings arm telemetry, demonstration capture, LeRobot
datasets, external and managed training, model artifacts, and policy execution
into one control plane.

You run ctrl-π on the Linux machine connected to the arms. PostgreSQL,
Hugging Face, and Modal stay in infrastructure and accounts you control;
ctrl-π is not a hosted intermediary. It retains control-plane metadata and
pre-upload recording staging only in the storage you configure.

<Warning>
  ctrl-π has no authentication in V1. Bind it to localhost or a trusted,
  firewalled LAN. Never expose port 8000 or the Vite development server
  directly to the public Internet.
</Warning>

## Where state lives

| State | Owner | Examples |
| --- | --- | --- |
| Control-plane metadata | Your PostgreSQL database | Robots, recording summaries, training runs, deployments, non-secret settings |
| Artifact bytes | Your Hugging Face namespace | LeRobot parquet/video/metadata, model cards, policy weights |
| Pre-upload recordings | The ctrl-π host or Docker volume | Finalized MP4, synchronized JSONL, durable episode manifest |
| Live state | One ctrl-π backend process | Telemetry, camera frames, rig leases, action queues, latency |
| Inference compute | Your Modal account | One ephemeral, exactly owned App per real deployment |
| Managed training compute | Your Modal account | At most one nonterminal, exactly owned SmolVLA job; artifacts remain on Hugging Face |

The backend is the only component that talks to hardware or receives service
credentials. Private Hub media is proxied at an immutable revision, and Modal
endpoint credentials never enter browser code.

## Mock and hardware modes

Mock mode is the default. It supplies a leader, follower, synthetic camera,
and deterministic Stub inference while still exercising real FFmpeg,
recording, database, and LeRobot conversion paths. Hugging Face calls remain
real unless a test explicitly selects the fake Hub.

Hardware mode selects the fail-closed standard-YAM adapter and real Modal
compute. A missing device or credential remains visibly unavailable; ctrl-π
never silently substitutes mock hardware after a real-mode failure.

<Note>
  The V1 camera is synthetic in both modes. Real hardware support is limited
  to one standard SocketCAN YAM follower, one calibrated GELLO leader, and the
  `crank_4310` gripper. Complete the physical validation checklist before
  enabling motion.
</Note>
